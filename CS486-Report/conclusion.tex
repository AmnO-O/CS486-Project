\section{Conclusion}
\label{sec:conclusion}

Phase~2 successfully extended the CS486 Campus Space Management System from a static Phase~1 relational baseline into a high-concurrency, enterprise-ready database architecture. By addressing requirement changes (Task~08), updating logical/conceptual models (Task~09), and executing non-destructive schema migrations (Task~10), the system expanded to support instant bookings, maintenance escalation workflows, soft-gate fallbacks, and advisory notices without breaking Phase~1 invariants.

\subsection{Key Technical Accomplishments}

\begin{itemize}
    \item \textbf{Deterministic Concurrency Control:} The implementation of SQL Server Application Locks (\texttt{sys.sp\_getapplock} on \texttt{space\_booking:<space\_id>}) resolved the critical read--check--write race conditions (K1--K5). Dual-session parallel test execution (Task~13) empirically verified 100\% data invariant preservation ($Q_{BR1} = 0, Q_{NR6} = 0$) and eliminated unhandled database engine exceptions (\texttt{Msg 50000}) in client applications.
    \item \textbf{High-Volume Performance \& Analytical Scaling:} The system demonstrated scalability under a synthetically generated dataset of over 100{,}000 bookings spanning three academic years (Task~14). Targeted indexing strategies (Task~15) optimized analytical reporting queries (Task~16), reducing query execution times by an order of magnitude.
    \item \textbf{Structured Agentic Engineering Methodology:} Operating within a strict 16-task design pipeline enforced rigorous traceability between business rules, normalized relational models (3NF/BCNF), and executable T-SQL DML/DDL artifacts.
\end{itemize}

\subsection{Future Directions}

While the current architecture satisfies all Phase~2 operational requirements, future production deployments could explore:
\begin{enumerate}
    \item \textbf{Partition Pruning:} Implementing range partitioning on \texttt{bookings.requested\_start\_time} by academic semester to accelerate archival queries and partition maintenance.
    \item \textbf{Per-Day Lock Granularity:} If production monitoring detects heavy lock contention on ultra-popular spaces, migrating from per-space lock keys to per-space-day keys (\texttt{space\_booking:<space\_id>:<date>}) offers a documented tuning path.
\end{enumerate}
